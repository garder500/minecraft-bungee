# Vampyuyu network: working notes

Velocity proxy + Paper 26.3 servers (lobby, survival, creative) in Docker, a panel, and four Java plugins
(`arena-plugin` = Werewolf and the arena engine, `network-plugin`, `lobby`, `claims-plugin`). The resource
pack is in `resource-pack/` (art scripts in Python, shaders generated by `art/fx_shaders.py`).
All user-facing text is English (menus, HUD, chat); the user talks to Claude in French.

## Test procedure (do all of it, never just say "I did it")

1. **Unit tests**: `make plugin-test PLUGIN=arena [TEST=SomeTestClass]` (docker maven, silent when green).
   Pack and HUD: `make test-pack` (also `python3 scripts/test_hud_sheet.py`).
2. **Build and deploy to the local stack** (WARNING: the docker stack runs Paper 1.21.9 per `.env`, while the
   plugins declare `api-version: 26.3`: they do NOT load there ("Unsupported API version 26.3"). Test the plugins
   with `scripts/e2e_client.py` (own Paper 26.3), not on the docker stack.): `make plugin PLUGIN=arena` builds the jar, overrides it on
   lobby/creative/survival and restarts them. `make pack` rebuilds `resource-pack/dist/vampyuyu-menus.zip`
   (the servers read it at start, so restart them after a pack change). `make up` starts the local stack.
3. **Real screenshots are required for anything visible** (HUD, village, outline, cards, effects). A
   description or the HUD mock is not enough. Use the isolated headless client:
   `python3 scripts/e2e_client.py --scenario werewolf --shots <dir>` (also `shader`, `roles`, `tooltip`,
   `debughud`; `--keep` leaves server and client running; see the docstring of the script). It boots its own
   Paper on :25599 with the freshly built `arena-plugin/target/nexus-arena-engine.jar`, a vanilla 26.3 client
   (Prism offline instance `26.3`, Xvfb `:99`, Mesa lavapipe) with the real pack, and writes PNGs. Build the
   jar first (`make plugin-build PLUGIN=arena`). Look at the PNGs (Read tool) and describe what is on them.
   - `make hud-sheet` renders every HUD state to `resource-pack/dist/hud-sheet/` (a simulation by the pack's
     Python port, not the game; it caught mangled text at fractional HUD scales).
   - Never launch the user's own Prism instance or account for tests (`prismlauncher -l 26.3` uses their real
     Microsoft account and desktop). Use `e2e_client.py` only.
4. **Gameplay by hand on the local stack**: `/ww debug practice <bots> [player]` starts a practice game
   (phases capped at 15 s), `/ww debug phase skip`, `/ww debug force <player|botN> <role>`,
   `/ww rules mayor elected` turns on the mayor election (off by default: the mayor is dealt),
   `/ww debug hud <state>` previews a HUD without a game. Console commands:
   `docker exec vampyuyu-local-lobby-1 rcon-cli <command>`.
5. Before concluding: read the whole diff, run the tests again, and say what was NOT verified.

## Werewolf controls (arena-plugin, `werewolf/hud/ClickControls.java`)

- **Left-click** (like breaking a block, also on a far player, also with an empty hand) picks the player or
  practice bot under the crosshair; right-click uses the held hotbar button (skip, potions, sleep...).
  Slot 9 (last) holds the role card: its tooltip explains the role (text from `roles/*.json` `help`).
- Selection feedback (`VoteMarks`): an invisible glowing mannequin outline shown only to the voter (to all
  for an accused player). No glass boxes, no particles.
- Only `WerewolfAmbience.aim` writes the action bar (every 200 ms, resent only when it changes): a second
  writer made the timer flicker.

## HUD and pack

- The HUD is glyphs coloured `(78, 100 + element, parameter)` in the action bar; the core shader moves them
  (`art/fx_shaders.py`, geometry in `layout.py`). `CustomHud.java` and `art/hud_sheet.py` must stay in step
  (`scripts/test_hud_sheet.py` checks the glyph order). The time bar is the `fill` element, its width is the
  blue channel.
- Do not scale the HUD by a non-integer factor: the pixel-art text breaks (tried 0.85 and 0.75). To shrink a
  panel, repaint its sprites in `art/hud.py`.

## Sky platform and village

Every game builds a flying platform in `ww_sky` (`werewolf/sky/`, decor in
`src/main/resources/werewolf/decor/default.json`, `DecorConfig.java`). `village.width` (0 disables) adds a
ring of grass, cottages, trees and lamp posts around it; the block cap is `maxBlocks` (18000).

## Paper 26.x notes

- Player data lives in `world/players/data/<uuid>.dat` (not `world/playerdata/`): `PlayerInventoryStore.file`
  picks the folder that exists. The scripts that still use `playerdata` (world_archive, smoke tests) are
  unchecked on 26.x.
- Game rules were renamed (keep_inventory, advance_time...): the old string API throws "Unknown gamerule".
  `ManagementApi.BOOLEAN_RULES` maps the panel's stable ids to the typed `org.bukkit.GameRules`.
