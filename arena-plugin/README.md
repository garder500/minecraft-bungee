# NexusArenaEngine

The **Arenas** page at `http://localhost:5173/#arenas` is the operator interface. It uses the existing authenticated Go panel, CSRF protection, controller container-label checks and activity log. It does not require server OP or expose Redis or the private plugin API to the browser.

## First arena

1. Build a safe play area in an existing world. No world, floor or structures are generated by this plugin.
2. In **Arenas**, select the hosting backend, then **Create arena**. Choose an ID, display name, world, both bounding-box corners (including Y), and a safe spawn inside the box. Default coordinates are suggestions around that world's spawn; review them before saving.
3. Choose **Werewolf** or **Free play**, participant limits, time limit and protection flags. Empty block allowlists forbid participants from breaking/placing blocks. Existing claim-plugin protections continue to apply. Allowed block changes affect the real world and are not rolled back.
4. Save the configuration. Players join using `/arena join creative:your-id` or a network invitation. You can also add a connected player using the panel.
5. Start once enough participants have joined. **Stop & restore** returns everyone to their original state. Edit/delete is refused while the arena is occupied or playing.

There are no active arenas on initial installation. The example `presets/werewolf.json` is deliberately outside the loaded `arenas/` directory. Configuration files in `plugins/NexusArenaEngine/arenas/<id>.json` can be reloaded with `/arena reload` when arenas are unoccupied. Overlapping arena boxes are rejected. A session supports up to 45 players, fitting the 54-slot compass GUI.

## Game and isolation

`ArenaPreset` factories create `GamePreset` state machines. Register a custom preset using `ArenaManager.registerPreset`; lifecycle, protection and snapshots remain in the engine. `WerewolfPreset` supplies `WerewolfGame`; Free play demonstrates a generic protected session with no secret roles or voting.

Werewolf plays the whole Ultimate Werewolf role set (40 roles, see [docs/werewolf-roles.md](../docs/werewolf-roles.md)) with the plugin as moderator. The automatic cast follows the rulebook: one wolf up to 8 players, two up to 11, three up to 15, then one per five, plus a seer; it then adds the witch from 6 players, the hunter from 7, Cupid from 8, the guard from 10, the scapegoat from 11, the bear tamer from 12 and the Ultimate roles from 13 up, and fills the rest with villagers (a custom `roles` map replaces this; the vampires, cult leader, lone wolf, hoodlum and tanner only come with a custom cast). Like the card game, the story opens at night: each role is called in turn (Cupid, doppelganger and hoodlum on the first night only; then priest, guard, seer, wolves, vampires, witch, P.I., aura seer, sorcerer, spellcaster, old hag, cult leader, troublemaker, ghost), then discussion → day vote → night again, until the village eliminates every wolf and vampire, the wolves are as many as everyone else (parity), another team completes its goal, mixed lovers are the last two standing, or the time limit expires. The wolf hunt ends as soon as every living wolf picks the same victim; otherwise the most-voted victim dies when the timer runs out. A tied day vote asks once for a new vote among the tied players only; a second tie eliminates nobody (a living scapegoat still takes a tie at once). A tied night hunt kills nobody. A living witch is always called, even with empty flasks, and she is shown the wolves' victim even when the guard protects them; she picks a head, then presses DEATH to poison it, LIFE to save the victim and SLEEP to end her turn. Living players can change their day ballot until the deadline, take it back with a second click on the same head, or skip the vote; if everyone skips, nobody is eliminated. During the vote each player's ballots show under their name tag ("✖ 3 votes"). When it closes, the verdict is announced in daylight: the eliminated player dies in front of the village (title, chat line with their role) a few seconds before night falls. Wolves vote only against non-wolves; the seer privately inspects one player each night. Eliminated players remain inside the area as non-interacting observers. They cannot vote, interact or share chat with living players, and living players cannot chat at night. No role carries a tell-tale item: menus open by themselves when a role wakes up. Roles and nightly ballots are never exposed in panel status.

The slot-8 compass is marked with a persistent-data tag. Its menu shows living player heads, visible vote totals, a private role reminder, phase timer and leave button. Drag/drop/hotbar/swap paths are protected; all drops and pickups are blocked during participation. Commands are restricted to the arena menu and leaving, so `/menu`, `/fly` and teleport commands cannot bypass the session. Operators can still deliberately override game state through the server console.

The virtual world border uses Paper's [`Player.setWorldBorder`](https://jd.papermc.io/paper/26.3/org/bukkit/entity/Player.html), backed by client border packets. The global world border is never changed. Minecraft can display only a square border: the visual square encloses the box, and server movement checks enforce the exact rectangular X/Y/Z limits. Other players keep their normal border and gameplay. PvP is blocked across arena boundaries; Werewolf always disables direct combat. World-space isolation does not hide participants from nonparticipants or undo environmental changes by unrelated players; use existing claims to protect the build itself.

## Persistence and recovery

Before clearing any belongings, the engine atomically writes and fsyncs a journal in `plugins/NexusArenaEngine/snapshots/<uuid>.yml`. It preserves every inventory/equipment/offhand slot (including newer Paper equipment slots), ender chest, XP level/progress/total, potion effects, position/rotation/world, mode, health, hunger, saturation, exhaustion, flight, speeds, air, fire, absorption and collision/invulnerability flags. Return teleport must succeed before restoring the state; the journal is deleted only after restored player data is saved. A disconnect retains the journal and restores on the next login. A failed restoration keeps the player locked and reports the pending recovery; repair the original-world availability and retry leaving. Never delete a journal to bypass an error.

The journal records the exact Minecraft version and refuses restoration under another version. Stop occupied arenas and verify their journals are gone **before updating Minecraft or rolling back images**. Stop servers and Redis for a consistent backup of the existing state directory, which includes JSON configurations, journals, local ban caches, Redis AOF and worlds. Do not restore only a stale player journal after that player has resumed ordinary play.

The engine is compiled for Java 25 / Paper API 26.3 and is exercised on the stack's Paper 26.3 servers. It uses [entity schedulers and asynchronous teleportation](https://docs.papermc.io/paper/dev/folia-support/) for player mutations, and pure synchronized game state for timers/votes. The plugin declares Folia support; a real Folia runtime validation remains required before switching this network to Folia. Existing VampyuyuNetwork/Lobby plugins and claims require their own Folia compatibility review. On Folia shutdown, journals are retained for login recovery instead of touching entities owned by other regions. The stack remains Paper.

## Redis and cross-server operations

Compose runs private Redis 8.2.9, pinned by digest, with AOF persistence, password authentication, no eviction and no published host port. Run the existing `network secrets` operator command to create `arena_redis_password` without rotating current credentials. Existing installations need this new secret before updating Compose. Keep `state/redis` writable by PUID/PGID. The private arena API listens on 8085, uses `role_bridge_token`, and is reached only through the controller. It accepts fixed operations, never arbitrary commands or shell access.

* `server:moderation`: `{"action":"BAN","targetUuid":"canonical-lowercase-uuid","reason":"..."}`. KICK disconnects locally without persistence; BAN is recorded centrally in `nexus:bans` and checked on backend login. UNBAN removes a network ban. Local caches cover Redis outages; reconnect resynchronizes them. Publishers must update the central ban hash before publishing BAN/UNBAN, as `RedisManager` does; publishing an event alone is not a persistent central ban.
* `server:announcements`: payload includes `id` (unique event UUID), `server` (`lobby`, `creative`, `survival`), `arenaId`, `name`, `message`, and `sentAt` (epoch milliseconds). Each backend renders text with an Adventure click/hover component; messages cannot inject MiniMessage actions. Events expire after 60 seconds and are deduplicated in a bounded cache.
* A remote invitation executes `/arena join server:id`. A 30-second, one-use Redis handoff precedes a supported BungeeCord `Connect` plugin message. Destination login consumes the handoff and joins the local arena. Velocity's existing BungeeCord channel support must remain enabled. An invitation cannot bypass login, a full/started arena or its rules. If transfer fails, the player keeps their restored original state and can retry.

Redis Pub/Sub is not a durable queue. Events during an outage may be missed; persistent bans are resynchronized on reconnect. Local arenas continue operating, while panel cross-server actions explicitly report Redis unavailability. A player already on a backend that is partitioned may remain until Redis reconnects; there is no false claim of instantaneous enforcement during a partition.

The panel exposes network kick/ban/unban in Arenas. Existing per-server bans in Players remain independent; removing a network ban does not remove a backend ban. Cosmetic role permissions still cannot grant `/op`, `/gamemode` or arena administration.

## API and validation

* `GET /api/v1/servers/{id}/game/arenas`: configurations, phase deadlines, alive participants, online players, loaded-world metadata, Redis status, network bans. Secret roles are excluded.
* `POST /api/v1/servers/{id}/game/action`: `arena-save` with `config`; `arena-delete/start/stop/announce` with `arenaId`; `arena-join/leave` with `uuid`; `arena-ban/kick/unban` with `uuid` and `reason`; `arena-reload`. Announce also requires `message`. All mutations require the administrator session, matching Origin and CSRF token and are audited without chat contents or secrets.

CI compiles/tests the arena module through the server/lobby image build and publishes it inside the existing immutable `server`/`lobby` commit-tagged images. Unit tests cover role allocation, vote privacy, seer limits, phase restrictions, ties, winners and bounding boxes. Go tests cover private proxy routing, operation allowlists, CSRF/auth and managed-JAR protection.

For a local integration smoke on otherwise empty servers:

```sh
npm install --prefix /tmp/nexus-smoke --no-save minecraft-protocol@1.68.0
NODE_PATH=/tmp/nexus-smoke/node_modules node scripts/smoke-arenas.cjs
```

It uses disposable UUIDs and correctly signed private forwarding, never changes public online-mode authentication, refuses to run while real players are connected, creates/removes a temporary arena, and tests real inventory restoration, private border packets, compass GUI, phases, Redis invitations and network bans. It leaves fixture UUIDs in `/tmp/nexus-arena-smoke-fixtures.json` for stopped-server cleanup. Real authenticated Velocity transfer and live Folia runtime verification must be done separately.

## Expanded casts and free-play objectives (1.1)

The panel's arena editor includes **Automatic cast** or exact role counts. Automatic casting follows the rulebook's wolf table and adds roles as the table grows (see above). Each role has a maximum count (masons up to 3, vampires up to 6, most roles once). Custom counts must fit the minimum participant count, with the killers (wolves and vampires) strictly in the minority. The GUI always shows the viewer's private role instructions.

* **Cupid** selects two lovers on the opening night; if time runs out first, nobody is bound and Cupid is told. A lover's elimination also eliminates their partner. A surviving mixed wolf/village couple has a Lovers victory when only they remain.
* **Hunter** gets a timed final-shot phase after game elimination, including elimination through a lover. Winner resolution waits for the shot or its timeout. The shot keeps the time of day it interrupts: a hunter killed at night shoots at dawn, in daylight. A disconnected hunter forfeits the shot.
* **Witch** gets a potion phase after the wolf hunt: one heal and one poison for the entire game. While she holds the healing potion she is shown the wolf victim (even one the Guard protects) and can save them; poisoning takes two clicks on the same living head. Both resolve at dawn. A living witch is called every night, even with empty flasks.
* **Guard** protects one player each night, including themselves, but cannot protect the same target on consecutive nights.
* **Seer**, **Werewolf** and **Villager** retain their inspection, hunt and day-vote actions. Sleeping phases keep every living player silent, wolves included; observers cannot communicate with living players through arena chat.

Free play now has five objectives: **Sandbox**, **PvP points**, **Break blocks**, **Place blocks**, and **Checkpoint race**. Configure a target score (laps for a race), points per action, temporary starting kit, six optional potion effects, flight, hunger, personal time/weather and player instructions. Kits reserve the compass slot. PvP requires the world's PvP setting to be enabled; normal world/claim restrictions still apply. Valid opponent defeats score points and respawn the victim at the arena spawn without dropping items. Environmental damage never awards PvP points. Block objectives count only successful uncancelled actions involving the allowlisted blocks. Repeated building/breaking can score repeatedly: choose allowlists appropriate to your game and prepare sufficient materials/terrain.

Races require at least two non-overlapping checkpoint spheres inside the play area, reached in order; repeated movement inside the same checkpoint does not advance past the next checkpoint. First to the goal wins; at the time limit a unique high scorer wins, otherwise it is a draw. The compass and action bar show scores, and the panel follows them live. Personal weather/time and the full original ender chest are included in snapshot restoration. `presets/freeplay.json` provides a reviewable duel template; it is not activated automatically.

## Lobby maintenance

The protected Lobby now has explicit operator maintenance mode: `/lobbybuild on` and `/lobbybuild off`, also available under **Server settings → Lobby → Build & inventory access**. It requires OP or `vampyuyu.lobby.build`; cosmetic roles do not grant it. Build mode enables block editing and inventory movement/disposal, then restores the previous game mode when disabled. It is temporary and clears on disconnect/restart. Join an arena only after disabling maintenance mode.

Explosions, fire damage to blocks, entity griefing and natural hostile spawns are prevented in the Lobby. Compose uses Peaceful difficulty and disables duplicate vanilla spawn protection, since the plugin explicitly protects all visitors. These changes apply to the Lobby only. The existing world is preserved.

Arena corners can be entered in either order: the panel and server normalize all three axes on save, retaining decimal coordinates. Spawn fields always display X / Y / Z, followed by yaw and pitch. Width/height limits, world-height checks, spawn containment and overlap checks still apply after normalization.

The local Creative `werewolf` arena is configured for X 1241–1315, Z -982–-887 and full world height (-64–320). Its checked arrival is X 1286.5 / Y 91 / Z -944.5, above stone-brick stairs with clear headroom. These coordinates belong to the imported Creative map; new deployments must review their own map.

### Solo practice

In the panel, select a waiting Werewolf arena and use **Solo practice → Start practice**. Choose a connected player if nobody has joined yet (a single eligible player is selected automatically), then choose the number of virtual participants. The default is seven, bounded by the configured minimum/maximum total player count. The real player joins through the normal snapshot/teleport path before the game starts. No real player is moved until the administrator confirms.

Virtual participants are labeled `[Bot] Guest N` in the panel and compass. They receive ordinary randomized secret roles and act through the same rules as a click, each at a random moment of its turn, so their ballots appear under name tags while the vote is open. Every role acts: Cupid binds two lovers, the guard protects someone (never twice in a row), the seer inspects players she has not seen yet, the witch saves the wolves' victim most of the time, sometimes poisons and then goes back to sleep, and a dead bot hunter shoots. A bot only uses what its role may know (its pack, its lover, its visions, the witch's victim, public ballots). Bot wolves never split the pack: they follow a real wolf's pick as soon as it is made and line up behind one victim at the deadline. In the day vote bots follow the leader, vote at random or skip; a seer votes against a wolf she saw; nobody votes against their lover or their pack. If the vote is still tied at the deadline, bots move to one of the leaders so the day is decided. When the timer runs out, every bot that has not acted yet acts at once. Each bot click is written to the game log (see Werewolf game logs) with the game's answer, like a player's. Bots do not simulate conversation. Practice phases last at most 15 seconds; normal game timings remain unchanged. Bots never connect to Minecraft, appear in TAB, spawn NPC entities, create player accounts or write inventories/snapshots. Their presence is in-memory only.

Stop/winner restoration clears all bots. The last real player leaving/disconnecting also clears the virtual cast and returns the arena to waiting. Real snapshots retain the existing restore-on-stop/reconnect/crash behavior. Free play and real-only Werewolf starts continue to use their normal rules. Authenticated `arena-practice-start` accepts `arenaId`, integer `botCount` (1–44, also constrained by the arena limits), and optional connected player `uuid`. Invalid limits and empty real-player games are rejected.


`scripts/smoke-practice.cjs` checks authenticated start, invalid counts, virtual player flags, phase progression, absence of bot saves, stop cleanup and last-human disconnect/reconnect restoration on an empty disposable Survival server.

## Village immersion and in-game administration (1.3)

Werewolf nights now run **Guard → Seer → Wolves → Witch** (after Cupid on the opening night), skipping absent/dead roles; a living witch is always called, even with empty flasks. The Guard and Seer turns end as soon as they act. `nightSeconds` applies separately to Guard, Seer and Wolves. Cupid and Hunter retain their special phases. Living sleepers receive blindness. Private role cards and actions use role colors; public messages never reveal a role through its color.

The wolves gather at their turn's beginning. **The hunt closes as soon as every living wolf picks the same victim**; votes can change until then. Otherwise the most-voted victim dies at the timeout. All wolves return automatically to their assigned homes when the hunt ends. A tie or no ballots produces no victim. Teleports must finish before the next phase accepts actions; failures interrupt the event and restore players.

| Admin command | Behavior |
| --- | --- |
| `/arena admin` | Paged browser, creation and confirmed deletion |
| `/arena corner1`, `/arena corner2` | Capture each bounding corner |
| `/arena create <id> <werewolf\|freeplay>` | Confirm creation with selected corners and current spawn |
| `/arena setup <id>` | Bounds, spawn, durations, limits, protection, ambience and rewards |
| `/eventadmin rewards <id> <participation> <victory>` | Set rewards; each amount must be 0–100,000 |

### Admin tools in your inventory (1.5)

`/arena tools [id]` gives hotbar items (tagged, undroppable, removed on quit or with `/arena tools off`); the setup menu has a **Get admin tools** button. `/arena select <id>` picks the arena they act on (automatic when only one exists). Every action answers in chat and the action bar; holding a tool shows spawn, houses, meeting/day points, doors and bounds as particles.

| Item | Right-click | Left-click / sneak |
| --- | --- | --- |
| Arena selector (map) | next arena | previous arena |
| Bounds wand (golden axe) | block = corner 2 | block = corner 1; sneak + right = apply to the arena (+5 blocks headroom) |
| Arena spawn (compass) | set spawn here | — |
| Readiness checklist (book) | ✔/✘ list of what is missing | sneak + right: open setup menu |

Every Werewolf game plays on its own **flying platform**: when the game starts, the plugin builds a round platform around a campfire at height 200 in the void world `ww_sky` (slot *i* of the world is centred at x = *i* x 256, so concurrent games never touch), with one seat per player and practice bot on a ring whose radius grows with the table (4 to 45 seats). Everybody is teleported to a random seat, sits on an invisible chair looking at the campfire and cannot walk off; practice bots appear as mannequins on their seats so they can be clicked like players. Nobody is moved afterwards, even at night: a sleeper's screen goes completely black (core shader plus blindness and darkness) and every other player and practice body is hidden from them; players awake at night see only the living. When the game stops, or a player leaves, players are restored to where they were before they joined (inventory, stats and position snapshot), the platform is removed and its slot is freed. The arena zone (bounds and spawn) is only the lobby where players wait. There are no houses and no doors any more; old `village` settings and old `places` blocks (seats and vote circle) in existing arena files are ignored and left untouched in the file.

The checklist and the start error say exactly what is missing; `/ww check` also tells whether the `ww_sky` world is ready. The plugin creates `ww_sky` itself when it enables (and discards any older copy, since platforms are ephemeral). If the server forbids creating worlds at runtime (Folia), pre-create it in `bukkit.yml` (`worlds: ww_sky: generator: NexusArenaEngine`) and restart; a game refuses to start while the world is missing. A table seats 4 to 45 players.

### Shards and global participation history

Normal completion gives each real participant **10 Shards**, plus **5** for a win. Eliminated players who stay remain eligible, including eliminated members of the winning camp. Lovers victory rewards only the surviving couple. A timed draw or sandbox completion gives participation only. Bots, practice, abandonment, operator stop and interruptions give zero; real-player history records their outcome.

`/profil` on all three backends opens the personal balance/history menu outside an arena. Balances and history live in the central SQLite database. During an outage the menu reports unavailability rather than showing a false zero. Configure the display name through the panel's `NETWORK_CURRENCY_NAME`, default `Shards`.

`/moneyadmin give|take|set <player|uuid> <amount>` requires `vampyuyu.money.admin` (OP by default), or server console. Names resolve through that backend's known-player cache; use UUIDs for remote players. Corrections use integer amounts from 0 to 1,000,000,000, cannot overdraw, and record actor/server. No shop or player transfers are included.

Authenticated private `POST /bridge/profile`, `/bridge/events` and `/bridge/money` extend the existing bridge. Event IDs and correction IDs prevent duplicate credits; conflicting retries fail. Each result batch and its credits commit transactionally. `results/active` journals interrupted games; final payloads move atomically to `results` and retry every five seconds until acknowledged. Include these directories and the SQLite database in backups. Deploy the panel and both plugins together after emptying arenas.

## Immersive Werewolf ambience (1.4)

Werewolf now uses native Minecraft sounds and English titles, without a resource pack. The opening reminds each player of their own role. A low bell announces dusk once per night; a gentle chime announces dawn. Voting and normal completion have shared cues. Guard, Seer, Wolves, Witch, Cupid and the pending Hunter receive their own colored wakeup and instructions privately, after spatial transitions succeed.

Living wolves hear two soft heartbeat pulses, 250 ms apart, every four seconds during their hunt. The first pair follows arrival at the meeting point. The last required vote or the hunt deadline immediately invalidates further pulses. There is no daytime ambience loop.

The action bar shows the active player's instruction and remaining time, with the last five seconds highlighted. Sleeping players and observers see only **The village sleeps** during secret turns. The compass applies the same privacy policy to phase labels, head descriptions and the phase timer; the administrator panel keeps its actual phase/deadline information. The eliminated Hunter retains private instructions while their final shot is pending.

Toggle **Immersive ambience** in `/arena setup <id>` while the arena is empty. It persists as `werewolf.ambienceEnabled`; absent or null values default to `true`. The web editor preserves this setting. When disabled, sounds and music are omitted (centre-screen titles stay), while English chat instructions, action bars and private compass information remain available.

All delayed cues are guarded by game identity and transition generation, plus current membership, phase and recovery state. Leaving clears the role title and action bar; stopping invalidates pending cues. A normal conclusion is shown before restoration and fades naturally. Free play keeps its existing presentation and scoring.

With the dependencies described in the isolated integration section, run:

```sh
AMBIENCE_SMOKE_ONLY=1 NODE_PATH=/tmp/community-smoke-node/node_modules node scripts/smoke-community.cjs
```

This variant inspects each forwarded client's sound, title, action-bar and compass packets. It checks private wakeups, heartbeat pairs, one dusk bell, end-of-vote/timeout behavior, muted presentation, restoration cleanup and the victory conclusion. Existing worlds and the running network remain untouched.

## Playing a werewolf game: no chest, a custom HUD

**No double chest during a game.** Look at a player (or a practice bot's body) and **left-click** (as if breaking a block, even from far away) to vote, inspect, protect, hunt or aim; right-click uses the held hotbar button. Slot 9 holds your role card (hover for how to play it). The other actions are hotbar items with a tooltip: Skip the vote, Life potion, Death potion (pick a player first), Sleep, Bind the lovers (after picking two players), Shoot (after picking a target), Protect yourself, Infect. The action bar names whoever your crosshair is on. `/ww vote <player>` and `/ww abstain` do the same by command. The only chest-style screen left is the pre-game lobby overview.

**The HUD is drawn by the resource pack** (`resource-pack/art/hud.py`, 120 sprites, font `vampyuyu:hud2`), not by Minecraft's bossbar and sidebar: the plugin writes glyphs coloured `(78, 100 + element, parameter)` in the action bar and the core shader (`text.vsh`, generated by `art/fx_shaders.py`) moves each one to its place in GUI pixels. Top centre: the phase plate (moon, sun or ballot icon, round, phase name such as `SEER AWAKE`, the turn's time as `mm:ss` and a draining bar) in the colour of your role; sleepers see `VILLAGE SLEEPS` and the time, nothing about who is awake. Right: your own role (icon, name, team) `ALIVE n/n`, a table strip with one dot per seat (you, your ballot, your pack mates or lover, the fallen) and status badges (lover, potions left, infection). Your ballot also shows as a glowing outline around the player you picked (only you see it), and practice bodies show their vote counts. Eliminated players get a grey `FALLEN` panel. Players without the pack get the vanilla bossbar and sidebar. Icons are in `art/icons.py` (font `vampyuyu:icons`).

**Sounds and music** (pack): `vampyuyu:werewolf.*`, built by `resource-pack/art/sounds.py`; narrator cues and role actions, plus a per-player ambient bed that follows the phase. `src/main/resources/werewolf/ambience.json` maps each phase (`lobby`, `day`, `night`, `vote`, `trial`, `finale`, with `DAY_VOTE` / `DEFENSE` overrides) to a looping bed (`sound`, `loopMillis`, `volume`), a transition sting and a vanilla fallback. `AmbienceDirector` decides the rest: when the bed changes the previous one is stopped and the new one started (category `ambient`); an unchanged bed is re-triggered only when its `loopMillis` has run out. Stings (`night`, `dawn`, `vote`, `howl`, `death`, `game_over`) take their sound and volume from the same file. Players without the pack hear the entry's vanilla fallback at low volume, at most once every 90 s. Everything stops when the game ends or the player leaves, and nothing plays when **Immersive ambience** is off. The server log records each bed change as `[ambience] bed <player> <phase> -> <sound>`.

**Night effect** (pack, core shader): a blue vignette at night and a warm wash at dawn, thinned over the HUD so it stays readable.

| `/ww debug peek`, `act <player\|botN> select\|aim <target> \| use <ability>`, `click <player> <target\|ability:name>` | List every role, act as someone, right-click as a player |
| `/ww debug hud <stateId\|phase\|role> [player]` | Preview a synthetic HUD for 10 s, no game needed (`nexusarena.admin`; from the console name a player) |
| `/ww debug hud list [filter]`, `cycle [seconds]`, `stop`, `size auto\|large\|medium\|small` | List the state ids, walk through all of them (default 4 s each), stop, preview a size mode without saving it |
| `/ww debug ambience <phase> [player]` | Print the resolved ambience entry (bed, sting, fallback) and play its sting when the pack is active |
| `/ww debug sky <players>` | Print the sky platform layout numbers for that many players (4 to 45) |
| `/ww debug help` | The same list in game |
| `/ww vote <player>`, `/ww abstain`, `/ww hud auto\|large\|medium\|small` | Players' commands |

The old spellings `/ww practice`, `force`, `act`, `click`, `peek` and `phase` still work as aliases of `/ww debug ...` (players see a one-line hint).

Roles: Villager, Werewolf, Seer, Witch, Hunter, Cupid, Guard and new in 1.6 **Alpha wolf** (his night vote counts double), **Infector** (once per game the victim becomes a wolf instead of dying), **Wolf cub** (when he dies the pack kills two players the next night), **Scapegoat** (dies when the day vote is tied) and **Bear tamer** (at dawn everyone hears a growl if a living wolf sits next to him). The automatic cast adds the scapegoat from 11 players and the bear tamer from 12; the new wolf roles come with `/ww cast set` (the wolf side wins and loses together). Not implemented: little girl, pause and resume.

### Variants (`/ww rules`, or the panel's arena editor)

| Setting | Default | Does |
| --- | --- | --- |
| `voting` | `point` | `point`: everybody right-clicks the player they suspect, the most pointed at falls (a tie is voted again among the tied players). `nominate`: the Ultimate Werewolf way: right-click to nominate, another player right-clicks the same player to second, the accused defends for 20 seconds, then everybody gives thumbs up or down (hotbar buttons); more than half of the living down and the accused is eliminated, else the debate resumes until the day's time is spent. |
| `reveal` | `full` | What a death tells the table: the `full` role, the `team`, only `wolf` or not, or `none`. With anything but `full` the dead roles are still called every night, for a few seconds, so the silence tells nothing. |
| `ballots` | `open` | `secret`: nobody sees the running count; the ballots are opened when the vote closes. |
| `dice` | off | Every dawn two dice pick a twist: the next victim becomes a wolf (2), a lightning vote at three ballots (3), two eliminations (4), the seer's last look is named (5), nothing (6-8), same as yesterday (9), secret ballots (10), a silent day (11), the next victim only loses their power (12). |
| `mayor` | `dealt` | `dealt`: the Mayor is a secret card. `elected`: no mayor card; the village votes for one on the first day (and again whenever the mayor dies), a crown floats over the elected mayor, and their vote counts twice in the vote and at the trial. |
| `minion` | `dealt` | `dealt`: the Minion is a card. `picked`: the standard rule, no card: on the first night the wolves agree on a player, who plays for the wolves, learns the pack, does not wake with it, keeps their own role and looks like a villager to the Seer. |
| `amulet` | off | A hidden player (never a wolf) holds the Amulet of Protection: it saves them once from any death, and they may pass it on each night; a player who already held it destroys it, and so does an unused amulet that saved a life. |

What the board game asks a moderator to judge is adapted: the mason taboo is not enforced; the ghost's letter is one letter typed in the chat. A player the old hag sends away really leaves the table for the day: black screen, invisible to the others, no chat and no vote, until nightfall, and everybody is told who is away. A player the spellcaster silences cannot chat but still votes and can gesture (move, crouch, look), and the table is told who is silent.

### Testing every role

`make e2e-pack` boots a creative Paper 26.3 and a headless 26.3 client with the real pack; `python3 scripts/e2e_client.py --scenario werewolf` plays a whole practice game, and `--scenario roles [--only SEER,WITCH]` plays one game per role with you holding it, through real controls, checking the game's journal for each (see `scripts/e2e_client.py`).

## Werewolf game logs

Every werewolf game writes its play-by-play to
`plugins/NexusArenaEngine/logs/werewolf/<date>_<time>_<arena>_<game>.log` (the 300 newest files are
kept) and mirrors each line to the server console under `[Werewolf]`; set
`WEREWOLF_LOG_CONSOLE=false` to keep the console quiet. Each line carries the clock time, the time
since the start, the game id, the day or night and the phase:

```
18:56:00.143 +01:12.4 [abcd1234] [Night 2 NIGHT] HUNT     The wolves' victim: Bob[SEER] · Ann→Bob, Zed→Bob
```

The journal covers the deal (every card and timer), each phase change and how long the last one
lasted, every timer start and expiry (and when a presentation holds the clock), every click with
the game's answer or the reason it was refused, menu clicks that were ignored (stale menu,
presentation running), the vote tallies, the wolves' choice, guard and witch saves, every death with
its cause, the hunter's shot, departures, the winner and the final roles, and the arena's stop.

The panel lists the logs under **Arenas › Game logs** and downloads them; a running game's log
downloads as far as it is written. The arena API serves them at `GET /arenas/logs` and
`GET /arenas/logs/<name>`.
