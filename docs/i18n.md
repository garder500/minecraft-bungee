# Languages (i18n)

English, French and German (`en_US`, `fr_FR`, `de_DE`). English is the source of every text and the fallback.

## Which language a player reads
1. The one chosen with `/lang fr|en|de` (`/lang auto` clears it). Stored on the player (PDC key `vampyuyu:lang`, a tag
   like `fr_FR`), so every plugin of a server can read it without depending on the network plugin. Per server for now
   (not yet shared by Redis between servers).
2. Else the language of the Minecraft client (`Player#locale()`).
3. Else English.

## Network plugin (`network-plugin/.../i18n`)
- `Lang`, `LangChoice`, `Translations`: pure Java, unit tested. `I18n` (Bukkit): loads `lang/<tag>.yml` of the jar
  (flat dotted keys, MiniMessage, `<name>` placeholders), then a same-named file in the plugin's data folder overrides
  single keys. `I18n#msg(sender, key, "name", "value"...)` returns a Component; placeholder values are plain text, never
  parsed. Reach it with `NetworkDisplay#i18n()`.
- Missing key in a language: English text, then the key itself. `python3 scripts/check_lang_parity.py` fails on an
  unknown key, a changed placeholder, or (network plugin) a key a language does not translate; `LangFilesTest` does the
  same in the build.

## Claims plugin
`ClaimLanguage` keeps the server language (config `lang`) plus `en`, `fr`, `de` read from the jar (`langs/*.yml`, with
the data folder's file overriding single keys). The command executors call `setViewer(sender)` around a command, so
`getMessage(key)` answers in the sender's language; `getMessage(key, player)` does too. Translations are partial: a key
a language lacks uses the server language. Done: chat, deny and enter/leave messages. Not yet: GUIs, help, maps,
Bedrock menus, and messages sent outside a command (events, GUI clicks) still use the server language.

## Survival: quests
Names and descriptions of the quests and of the quest categories are translated (fr, de). The English text stays in
`quests.sql` / `quests_daily.sql`. Translations live in `scripts/i18n/quests.fr.json` and `quests.de.json` (key = quest id,
or `cat:<category id>`), `python3 scripts/gen_quest_i18n.py` writes the seed `db/seed/quests_i18n.sql` (tables `quest_text`,
`quest_category_text`, migration V026; no foreign key, so re-seeding the quests does not wipe them) and fails when a quest
has no translation (`--check` only checks). `QuestCatalog#name/description(def, lang)` return the translation, else the
English text; the menus, chat messages, sidebar and /guide use `PlayerLang.of(player)` (same rule as above, read from the
player data key, no dependency on the network plugin). Quest texts keep the English names of custom items (Fountain,
Spring Stone, Forge, Bronzite...) until the items themselves are translated, so the words match what is on the items.
Not yet: the fixed texts around them ("Rewards", "Next:", menu titles) and item names/lore.

## Not translated (on purpose)
Text painted in resource-pack sprites (HUD, menu backgrounds).
